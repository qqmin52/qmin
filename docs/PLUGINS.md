# 插件开发指南

本文只写框架**当前实际支持**的能力。未封装的 SDK 能力会在最后一节列出，避免你按想象写代码。

## 1. 插件是什么

一个插件 = `plugins/` 目录下的一个 `.py` 文件，**文件名就是插件名**（去掉 `.py`）。

加载时框架会：

1. 按路径导入文件，模块名固定为 `qmin_plugin_<文件名>`；
2. 在导入过程中把装饰器注册的处理器挂到全局路由器上，并打上来源标记（插件名）；
3. 导入失败只影响该插件：错误写进插件记录 + 日志，其他插件与主进程不受影响。

命名规则：

| 规则 | 说明 |
| --- | --- |
| 只允许小写字母、数字、下划线，且以字母开头 | 例如 `weather`、`group_admin`、`hello2` |
| **不能以下划线开头** | 以 `_` 开头的文件会被跳过，用来放模板/私有文件（如 `plugins/_template.py`） |
| 单个文件不超过 256 KB | 面板安装时的限制 |
| 不能重名 | 面板安装同名文件时会拒绝，除非选择覆盖 |

## 2. 最小模板

```python
"""我的第一个插件：群里 @ 机器人并说“你好”时回复。"""

from core.handlers import on_group_at

# 可选元信息，面板会展示
__plugin_name__ = "打招呼"
__description__ = "收到包含“你好”的群消息时回复"
__version__ = "1.0.0"


@on_group_at("你好")
async def hello(event) -> None:
    await event.reply("你好呀")
```

仓库里的 `plugins/_template.py` 是同一份模板（带注释），可以直接复制改名使用。

## 3. 事件装饰器

目前**只有一个**事件装饰器：

| 装饰器 | 参数 | 匹配规则 |
| --- | --- | --- |
| `on_group_at(keyword=None)` | `keyword`：字符串或 `None` | `None` 匹配所有群 @ 消息；否则按**子串**匹配正文 |

要点：

- **子串匹配、区分大小写**：`on_group_at("你好")` 会命中「你好啊」「我说你好」。想精确匹配请在处理器里自己判断 `event.content.strip() == "你好"`。
- **按注册顺序执行，且不会短路**：一条消息命中多个处理器时，会依次全部执行。同一插件里写两个都命中的处理器，就会执行两次。
- **多个插件同时命中会各自回复**：如果两个插件都监听「你好」，群里会收到两条回复。设计关键字时尽量错开。
- 框架不对正文做 trim，正文可能带前导空格；用子串匹配不受影响，精确比较时请自己 `strip()`。

## 4. event 对象

处理器收到的是 `core.events.GroupAtMessage`（`frozen` 数据类，只读）：

| 字段 / 方法 | 类型 | 说明 |
| --- | --- | --- |
| `event.group_openid` | `str` | 群 openid（不是群号） |
| `event.content` | `str` | 消息正文（平台给的原文，可能带前导空格；框架不做 trim） |
| `event.sender_id` | `str` | 发送者 openid |
| `event.sender_name` | `str` | 发送者昵称，可能为空字符串 |
| `event.msg_id` | `str` | 本条消息 id |
| `event.timestamp` | `str \| None` | 平台给的时间字符串，可能为 `None` |
| `event.raw` | `Mapping[str, Any]` | 原始载荷副本，字段随平台变化，不建议依赖 |
| `await event.reply(text)` | `-> Any` | 发送被动回复（纯文本），失败会抛异常 |

示例：带上发送者昵称回复

```python
@on_group_at("hi")
async def hi(event) -> None:
    who = event.sender_name or event.sender_id[:8]
    await event.reply(f"hi，{who}")
```

## 5. 生命周期与热重载

### 什么时候加载

| 场景 | 行为 |
| --- | --- |
| `qmin start` 启动 | 扫描 `plugins/*.py`，逐个加载 |
| 面板「安装插件」 | 写文件 → 立即加载（失败会回滚文件） |
| 面板「重新加载」 | 先摘掉该插件的旧处理器，再重新导入文件 |
| 面板「禁用」 | 摘掉处理器，文件保留 |
| 面板「启用」 | 重新导入文件 |
| 面板「删除」 | 摘掉处理器 + 删除文件 + 从列表移除 |
| 手动往目录里放文件 | **不生效，需要重启** `qmin start`（没有文件监听） |

### 热重载的边界

重新加载会重新执行整个模块，因此：

- **模块级变量会重置**：写在模块顶层的计数器、缓存，重新加载后归零。
- **不会重启机器人连接**：重载只影响后续消息的分发，已建立的网关连接保持不变。
- **正在执行的处理器不会被打断**：重载对已经进入执行的那次调用没有影响。
- **不能靠重载改框架**：改 `core/`、`api/` 下的代码必须重启进程；热重载只针对 `plugins/` 下的文件。
- **处理器不会翻倍**：重载前会按来源摘除旧处理器，所以不会出现「回复两条」；如果你发现重复回复，多半是两个插件都监听了同一关键字。

## 6. 插件之间能互相调用吗

**不支持。** 每个插件是独立文件、独立模块，`plugins/` 目录不在 `sys.path` 里，所以 `import 另一个插件` 并不可靠。

推荐做法：

- 单个插件内部保持内聚，把公共函数放在同一个文件里；
- 需要跨项目复用的代码，做成独立 Python 包（`pip install` 后正常 `import`）；
- 不要把共享状态放在模块级全局变量里——重载会丢，多个插件之间也读不到。

## 7. 错误处理推荐写法

框架会给每个处理器兜底：抛出的异常会被捕获，写一条 `ERROR` 日志（来源 `handler`），然后**继续执行后续处理器**，不会影响主进程。

但对用户侧的失败，最好自己处理，给出可读的日志或回复：

```python
import asyncio

from core.handlers import on_group_at


@on_group_at("查天气")
async def weather(event) -> None:
    try:
        data = await fetch_weather(event.content)          # 你自己的异步调用
    except asyncio.TimeoutError:
        await event.reply("查询超时了，稍后再试")
        return
    except Exception as exc:                                # 兜底，避免异常冒泡成 ERROR 日志
        await event.reply("查询失败了，请联系管理员")
        raise                                               # 需要排查时再抛，框架会记日志

    await event.reply(data)
```

注意事项：

- **不要在处理器里做同步阻塞操作**（`time.sleep`、`requests`、大文件读写）——事件循环会被卡住，其他消息全部排队。用 `asyncio.sleep` 与异步 HTTP 客户端。
- `event.reply()` 是网络调用，可能因限流或超时失败，建议包在 `try/except` 里。
- 被动回复有时效（平台限制为收到消息后 5 分钟内），耗时任务请先回复再异步处理。

## 8. 调试

| 现象 | 看哪里 |
| --- | --- |
| 插件压根没加载 | `qmin doctor` 看「插件文件数量」；面板插件页看状态是否为「启用·加载失败」 |
| 加载报错（语法/导入） | 面板「日志」页筛选来源 `plugins`，错误里带行号与原因 |
| 运行时报错 | 面板「日志」页筛选来源 `handler` |
| 想确认消息到没到 | 面板日志里搜「收到群消息」；或在处理器里 `print` 到终端 |
| 想看 SDK 细节 | `.env` 里设 `LOG_SDK=all`，SDK 的 INFO 日志也会进面板 |

## 9. 常见坑

1. **文件名非法**：大写字母、中文、带空格、以 `_` 开头都会被拒或跳过。
2. **忘了重启**：手动放进 `plugins/` 的文件不会自动加载，要在面板点「重新加载」或重启。
3. **关键字太宽**：`on_group_at("好")` 会命中「你好」「好的」「好吃」……尽量用更具体的词。
4. **重复回复**：多个插件监听同一关键字，会各回一条。
5. **模块级状态丢失**：重新加载后归零，别把它当数据库用。
6. **在处理器里阻塞**：同步 IO 会卡住整个事件循环。
7. **改了插件却在看旧日志**：日志是落库的，记得确认时间戳。

## 10. 尚未支持

以下能力需要直接调用 qq-botpy SDK，框架层暂未提供装饰器：

- 按钮 / 卡片等交互组件（keyboard、ark）
- 私聊（C2C）消息
- 频道（频道 @、频道私信）消息
- 主动推送（非被动回复）
- 群成员变动、入群/退群等事件的业务处理（框架只记日志，不分发给插件）

如果你的场景依赖其中某项，欢迎开 issue 描述用途，会按需求排期。
